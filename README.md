# Yoko Shop

ქართულენოვანი მაღაზიის სტატიკური ინტერფეისი Supabase-ის სერვერთან.

## გაშვება

გახსენი `index.html` ბრაუზერში, ან გაუშვი საქაღალდეში ნებისმიერი სტატიკური ფაილების სერვერი. მაღაზიას ანგარიშის გარეშე დათვალიერება შეიძლება; შეკვეთისთვის რეგისტრაცია ან შესვლა აუცილებელია.

## რედაქტირება

- პროდუქტების საწყისი სახელები და ფასები შეცვალე `script.js`-ში; დამატებული პროდუქტები Supabase-ში ინახება.
- სტილები შეცვალე `styles.css`-ში.
- მაღაზიის გვერდის ტექსტი და საკონტაქტო ინფორმაცია შეცვალე `shop.html`-ში.
- რეგისტრაციის გვერდის ტექსტი შეცვალე `index.html`-ში, მის სტილებს — `auth.css`-ში.
- ბრენდის ლოგოს ფაილია `logo.png`.

მთავარი ბანერის, კატეგორიებისა და ამბის სექციაში დამატებითი ფოტოები ამოღებულია. კატალოგში დატოვებულია მხოლოდ მომხმარებლის მიერ დამატებული ფოტოები; სხვა პროდუქტებს ცარიელი ფოტოსივრცე აქვთ.

## Supabase-ის დაკავშირება

1. შექმენი Supabase პროექტი და `supabase-config.js`-ში ჩასვი Project URL და საჯარო publishable/anon key. **არ ჩასვა `service_role` ან secret key.**
2. Supabase Dashboard-ში გახსენი SQL Editor, ჩასვი `supabase-setup.sql` და გაუშვი. ის ქმნის პროდუქტებისა და შეკვეთების ცხრილებს, სურათების `product-images` bucket-ს, RLS პოლიტიკებს და შეკვეთის `place_order` ფუნქციას. სერვერი კატალოგიდან ამოწმებს ფასებს და თავად ითვლის მიწოდებასა და ჯამს, ამიტომ ბრაუზერში შეცვლილი ფასი შეკვეთაში არ მიიღება. ამ ვერსიის გამოსაქვეყნებლად უკვე არსებულ პროექტზე ეს SQL თავიდან გაუშვი — ის განახლებადია.
3. Authentication → URL Configuration-ში Site URL-ად მიუთითე `https://nodaribakuria.github.io/yoko-shop/`; Redirect URLs-ში დაამატე `https://nodaribakuria.github.io/yoko-shop/**` და ლოკალური ტესტირებისთვის `http://127.0.0.1:5500/**`.
4. Authentication-ის Email პარამეტრებში ჩართე ელფოსტით დადასტურება. პაროლის აღდგენის წერილის გასაგზავნად Supabase-ის Email/SMTP გამგზავნიც უნდა იყოს გამართული.
5. GitHub-ზე ატვირთე ფაილები. გალერიიდან მიღებული JPG/PNG/WebP/GIF ფოტოები მაქსიმუმ 5 MB ზომით იტვირთება `product-images` საცავში.
6. მფლობელის ანგარიშით ერთხელ დარეგისტრირდი საიტზე. შემდეგ Supabase Dashboard-ის SQL Editor-ში გაუშვი ქვემოთ მოცემული ბრძანება და `YOUR_SIGNUP_EMAIL` ჩაანაცვლე რეგისტრაციისას გამოყენებული ელფოსტით. ეს ანგარიში გახდება ერთადერთი, რომელსაც პროდუქტის დამატება/წაშლა და ფოტოების ატვირთვა შეუძლია:

   ```sql
   insert into public.store_admins (user_id)
   select id from auth.users where email = 'YOUR_SIGNUP_EMAIL'
   on conflict (user_id) do nothing;
   ```

   სტუმრებს კატალოგის ნახვა შეუძლიათ, ხოლო შეკვეთის გასაფორმებლად ანგარიშში შესვლაა საჭირო. სხვა ანგარიშები მყიდველებად რჩებიან და ვერ აქვეყნებენ პროდუქტებს. თუ მფლობელის ელფოსტა არასწორადაა მითითებული ან ანგარიში ჯერ არ შექმნილა, ბრძანება ადმინისტრატორს არ დაამატებს.

ანგარიშებს და პაროლებს Supabase Auth მართავს. შესვლისას Supabase-ის განახლებადი სესია მომხმარებლის ბრაუზერის localStorage-ში ინახება, ამიტომ პაროლის ხელახლა შეყვანა ჩვეულებრივ აღარ არის საჭირო. საიტში პაროლი არ ინახება; გამოსვლის ან ბრაუზერის საიტის მონაცემების წაშლის შემდეგ ხელახლა შესვლაა საჭირო. პროდუქტისა და შეკვეთების ჩანაწერები მონაცემთა ბაზაში, ფოტოები კი Storage-ში ინახება. `store_admins` ცხრილში მფლობელის ჩანაწერი პროდუქტების მართვას და ყველა შეკვეთის ნახვას RLS პოლიტიკებით ზღუდავს. მომხმარებელი ხედავს მხოლოდ საკუთარ შეკვეთას. GitHub Pages მხოლოდ საიტის ფაილებს ემსახურება.

შეკვეთის გაფორმებისას სახელი, ელფოსტა, ტელეფონი, მისამართი, კალათის ნივთები, მიწოდების ფასი და ჯამი ინახება `orders` ცხრილში. მომხმარებელი პროფილში საკუთარ შეკვეთებს ნახულობს; მფლობელს შეუძლია სტატუსის შეცვლა და შეკვეთების ნახვა. 150 ₾-ზე ნაკლებ შეკვეთაზე მიწოდებაა 10 ₾; 150 ₾-დან უფასოა. ამჟამად ხელმისაწვდომია მიტანისას გადახდა; ონლაინ ბარათით გადახდას რეალური გადახდის პროვაიდერის ინტეგრაცია სჭირდება და გამორთულია. საწყისი კატალოგის გარდა, პროდუქტის მაგალითები დემო მონაცემებია.

გასაყიდად დარჩენილია რეალური მარაგისა და დაბრუნების წესის მითითება, ასევე მაღაზიის მოქმედი ტელეფონისა და ელფოსტის დამატება. ონლაინ ბარათის ჩასართავად საჭიროა გადახდის პროვაიდერის ანგარიში და სერვერული ინტეგრაცია; secret გასაღები საიტის JavaScript-ში არ უნდა განთავსდეს.
